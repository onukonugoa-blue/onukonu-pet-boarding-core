LOGIN PAGE REFINEMENT – BRANDING ONLY

Context

The previous login-page implementation successfully branded the login experience but introduced custom layout behaviour.

The result is visually attractive but not pixel-perfect across all devices.

Some mobile devices require pinch-zooming because the custom card sizing and positioning interfere with WordPress's native responsive layout.

This refinement aims to simplify the implementation.

---

OBJECTIVE

Preserve branding.

Remove layout ownership.

Allow WordPress and Loginizer to control:

- Width
- Positioning
- Responsiveness
- Viewport behaviour
- Form layout

OPB should only control appearance.

---

IMPORTANT

Do NOT modify:

- Authentication
- Loginizer
- Redirects
- Sessions
- Cookies
- Portal routing
- Login flow

This is a CSS-only refinement.

---

DESIGN PHILOSOPHY

WordPress owns layout.

OPB owns branding.

---

KEEP

✓ Custom logo

✓ Brand colours

✓ Button styling

✓ Input styling

✓ Notice styling

✓ Subtle background

✓ Typography improvements

✓ Hover states

✓ Focus states

✓ Professional appearance

---

REMOVE

Remove any CSS that controls:

- Width
- Max-width
- Min-width
- Positioning
- Centering logic
- Flex layouts
- Fixed heights
- Viewport calculations
- Transform translations
- Custom card containers

Do not replace these with alternative layout systems.

Let WordPress render the page normally.

---

LOGO

Use:

assets/branding/login-logo.png

Keep the logo.

Do not use PWA icons.

Scale responsively.

Do not force dimensions that affect layout.

---

BACKGROUND

Keep a subtle branded background.

Examples:

- Soft navy gradient
- Light texture
- Subtle vignette

Must not affect responsiveness.

Must not introduce scrolling.

---

FORM STYLING

Only style existing WordPress elements.

Examples:

- Inputs
- Labels
- Buttons
- Notices
- Links

Do not wrap elements.

Do not inject containers.

Do not alter structure.

---

BUTTONS

Brand colour:

#1a365d

Hover:

slightly lighter navy

No animations.

No transforms.

No motion effects.

---

LOGINIZER COMPATIBILITY

Verify appearance for:

- Failed login
- Lockout notice
- 2FA challenge
- Forgot password
- Password reset

No structural changes.

No hidden elements.

---

RESPONSIVENESS

WordPress must remain fully responsible for:

- Desktop layout
- Tablet layout
- Mobile layout

No custom responsive system.

No viewport hacks.

No media-query-based layout overrides.

---

DELIVERABLES

Provide:

1. CSS selectors modified
2. CSS selectors removed
3. Screenshot summary
4. Loginizer compatibility verification
5. Files changed
6. Commit hash
7. Production ZIP

---

SUCCESS CRITERIA

✓ WordPress controls layout

✓ Loginizer controls security

✓ OPB controls branding only

✓ Custom logo displayed

✓ Brand colours applied

✓ Responsive behaviour unchanged from WordPress default

✓ No pinch-zoom required

✓ No scrolling issues

✓ Professional branded appearance

✓ Minimal maintenance burden
